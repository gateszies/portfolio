## Context

ProDPI is a direct-to-consumer print lab that specializes in custom prints, wall art, cards, and albums. Its website is the primary storefront, where customers choose sizes, materials, and finishes before designing their product in an editor.

I led a complete rebuild of the storefront, moving it off an aging CMS and onto a component-based system that engineers and marketers can both extend.

## Problem

### No shared architecture

The site had no component model. Every non-product page was its own template, and the 38 product pages were split across six templates that did essentially the same job.

```ansi
templates/
├── landing-fall-promo.twig
├── landing-holiday.twig
├── landing-spring.twig
├── landing-wedding.twig
├── product-prints.twig
├── product-wall-art.twig
├── product-cards.twig
├── product-albums.twig
├── product-canvas.twig
└── product-metal.twig
```

Every new page cost engineering time, and that cost grew with the site.

### Every section lived in one file

Pages on the site were built from sections, and each section type was a hand-coded case block inside a single `switch` statement.

```twig title="generalBuilder.twig"
{% switch block.type.handle %}

  {% case "fullHero" %}
    {% set img1 = block.heroImage.one() %}
    {% set transforms1 = img1.transforms %}
    {% set x = 'center' %}
    {% set y = 'center' %}
    {% if img1.hasFocalPoint %}
      {% set x = img1.focalPoint | first * 100 ~ '%' %}
      {% set y = img1.focalPoint | last * 100 ~ '%' %}
    {% endif %}
    <div class="hero-wide" style="padding: 80px 0;">
      <img src="{{ transforms1.src() }}"
           srcset="{{ transforms1.srcset() }}"
           sizes="100vw"
           style="object-position: {{ x }} {{ y }};"
           class="cover">
      <h1 class="hero-title">{{ block.heading }}</h1>
      <p class="hero-copy">{{ block.text }}</p>
      <a href="{{ block.linkUrl }}" class="btn btn-primary">
        {{ block.linkText }}
      </a>
    </div>

  {% case "splitHero" %}
    {% set img2 = block.sideImage.one() %}
    {% set transforms2 = img2.transforms %}
    {% set posX = 'center' %}
    {% set posY = 'center' %}
    {% if img2.hasFocalPoint %}
      {% set posX = img2.focalPoint | first * 100 ~ '%' %}
      {% set posY = img2.focalPoint | last * 100 ~ '%' %}
    {% endif %}
    <div class="split-hero" style="padding: 64px 0; background-color: {{ block.bgColor.hex }};">
      <img src="{{ transforms2.src() }}"
           srcset="{{ transforms2.srcset() }}"
           sizes="50vw"
           style="object-position: {{ posX }} {{ posY }};"
           class="split-img">
      <h2 class="split-heading">{{ block.headline }}</h2>
      <div class="split-text">{{ block.body }}</div>
      <a href="{{ block.ctaLink }}" class="button-dark">
        {{ block.ctaLabel }}
      </a>
    </div>

  {% case "textCallout" %}
    <div class="callout" style="padding: 48px 24px; background-color: {{ block.backgroundColor.hex }};">
      <h3 class="callout-heading" style="color: {{ block.textColor.hex }};">
        {{ block.title }}
      </h3>
      <p>{{ block.copy }}</p>
      <a href="{{ block.buttonUrl }}" class="btn-outline">
        {{ block.buttonText }}
      </a>
    </div>

  {# ...and the same again for every other section type #}

{% endswitch %}
```

Nothing documented how a section should look or what options it had. The code was the only spec, and nobody wanted to touch it because it was so fragile.

### The site had aged out

The site was still running on Craft CMS 3, two major versions and about six years behind. Years of campaigns had also left it full of outdated pages and duplicate copy. Before migrating anything, someone had to figure out what was worth keeping.

### Build on a shared foundation

With the design settled, I started building. Each section has its own file and shared pieces like images and buttons are written as components.

```twig title="media-text.twig"
{% set title = section.title %}
{% set body = section.body %}
{% set media = section.media.one() %}
{% set colorScheme = section.colorScheme.value %}
{% set mediaSide = section.mediaSide.value %}
{% set titleSize = section.titleSize.value %}

<section class="{{ rootClasses }}" data-color-scheme="{{ colorScheme }}">
  <div class="{{ innerClasses }}">
    <div class="{{ mediaWrapperClasses }}">
      {% if media.kind == 'image' %}
        {% include '_partials/picture' with {
          asset: media,
          class: 'cover',
          sizes: '(min-width: 1024px) 50vw, 100vw'
        } only %}
      {% endif %}
    </div>

    {% include '_partials/content-block' with {
      title,
      titleSize,
      body,
      links,
    } only %}

  </div>
</section>
```

The settings selected in the CMS become the `rootClasses` above, one modifier class per choice, so the markup reads like the section's settings.

```html
<section
  class="Section MediaText MediaText--mediaRight Section--compact Section--alignStart Section--mobileAlignCenter"
></section>
```

I also brought the full design system into the repo as tokens, with a semantic layer for color. This allows a brand color change to happen in one file.

```scss title="_theme.scss"
:root {
  --bgColor-neutral-primary: var(--gold-1);
  --bgColor-neutral-secondary: var(--gold-2);
  --bgColor-brand-strong: var(--ocean-12);
  --fgColor-neutral-primary: var(--gray-12);
  --fgColor-brand-strong: var(--gold-8);
}
```

I also moved the site's legacy jQuery to TypeScript and wrote the repo's coding conventions as rules for both humans and agents, so new work follows the same patterns.

### Consolidate the product pages

The same foundation let six product templates become one. A single field layout in the CMS covers every product, and details that used to need their own template, like an album's cover materials, became optional fields.

### Run the migration and launch

The new site was a brand-new Craft 5 project. Craft 3 was full of bugs it would never get fixes for, and starting fresh got the site current without working through two major upgrades.

It also meant there was no automatic path for content, so 50+ pages moved by hand in three phases:

- **Base content**: existing copy and images from the old site
- **Editorial content**: new copy written for the new sections
- **Field restructuring**: mapping old fields to new ones where the content model changed

I wrote the tickets, tracked progress weekly, and kept the other developers and the marketing manager in sync through testing and launch.
